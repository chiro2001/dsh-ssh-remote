# 0.13.9 acceptance — headless SSH search

Date: 2026-11-18. Plugin candidate: `0.13.9` built from the reviewed branch; helper `0.13.5` unchanged.

## Environment

- Independent DSH runtimes: `@deepseek-ai/dsh@0.2.1-rc.2` and `@deepseek-ai/dsh@0.2.2-rc.3`, installed under separate local prefixes. Neither used the globally installed DSH.
- Separate `DSH_HOME` and profiles for every runtime; the plugin was installed from the candidate `.tgz` into the `headless` profile.
- Real SSH: the host connected to `dshlab@127.0.0.1` through a temporary OpenSSH alias. The remote project lived at `/home/dshlab/project` with mode `0700`, so the host user could not read it locally. The alias and test user were removed after acceptance.
- No production profile, workspace mapping, SSH configuration or remote file was used.

## Before the fix

Started `dsh --profile headless` from the SSH workspace anchor:

```console
{"type":"session","sessionId":"session-212e…","cwd":"/home/dshlab/project"}
{"type":"status","phase":"turn_end","turn":1,"reason":{"kind":"error","error":{"message":"EACCES: permission denied, realpath '/home/dshlab/project/.git'","code":"UNKNOWN"}}}
```

The Session header was the bare remote POSIX path, so `grep` ran as the local user against an unreadable local path. On `ssh localhost` with the same path readable locally, the same bug can silently return local results.

## After the fix

Same runtime and anchor, with the candidate package:

```console
{"type":"session","sessionId":"session-f77c…","cwd":"<isolated DSH_HOME>/ssh-workspace-anchors/project · dshlab [e0d2659f]"}
...
"Found 2 files containing DSHLAB_MARKER…"
- /home/dshlab/project/remote-only.txt — line 1: DSHLAB_MARKER_UNIQUE
- /home/dshlab/project/src/app.ts — line 1: export const dshlab = "DSHLAB_MARKER_UNIQUE";
```

The SSH invocation log recorded the remote `rg` run for the workspace. A separate `glob` run on 0.2.2-rc.3 returned `./src/app.ts` with the same anchor cwd. The test `runtime-router.test.ts > keeps the headless Session cwd probe on the local SSH anchor` covers the router contract without a model request.

## Subagent path inheritance

The fixed headless parent was used for two children:

- Child A was delegated with **no `cwd`**. It inherited the parent anchor, reported `<anchor>`, and grep returned remote `./remote-only.txt` and `./src/app.ts`.
- Child B was delegated with `cwd: "/home/dshlab/project/src"`. It reported `<anchor>/src` and grep returned remote `/home/dshlab/project/src/app.ts`; the local host user still could not read the project.
- The same child then used relative `read app.ts`, relative `write probe-child.txt`, and `grep` with `path: "."`. All three resolved under `/home/dshlab/project/src`; `probe-child.txt` existed remotely and the local anchor stayed empty.
- Before the relative-root fix, the same child's `grep path: "."` returned `/home/dshlab/project/remote-only.txt` from the parent directory, because the relative root was resolved against the Host process cwd. After the fix it returned only `./app.ts`.

## Related model-tool audit

The affected Session-cwd seam is shared by the standard path tools, so the same fix applies to them. In the same isolated `dshlab` workspace I exercised the following after the fix:

- `read`, `write` and `edit` with absolute remote paths (`/home/dshlab/project/...`) created and edited `probe.txt` through the helper; relative paths were verified separately in the child above. The local anchor stayed empty and the host user still could not read the remote project.
- `bash` with `workdir: "/home/dshlab/project/src"` printed the remote path and the `dshlab` user; the existing `helper-shell-routing.test.ts` also covers raw absolute workdirs for all sandbox modes.
- `glob` and `grep` returned remote paths; `skill` discovered the remote-only `.dsh/skills/dshlab-probe` skill. A subagent grep was already exercised in the earlier run.
- `present` is not mounted in the headless profile; its implementation uses `workingDirectory.ensure()` plus `ctx.fs`, so it receives the corrected cwd instead of its own local resolver. `run_code`/PTC uses `resolveRemoteExecutionUri()` with the sandbox workspace root and has existing router/PTC regressions.

Two optional tools were not fixed because they are not in the default/headless composition and need a different contract:

- `dsh-tool-terminal` (experimental terminal bundle): its model-facing `cwd` argument can be an absolute remote path, but `installRemoteTerminalRouter()` currently recognizes only `ssh://` or a local anchor. The default anchor cwd works; an absolute remote override is not host-mapped. The isolated `terminals` service in that bundle also needs separate composition testing.
- `dsh-tool-str-replace-editor`: it accepts absolute paths only and calls `fs.resolve(path)` without a Session cwd, so an absolute remote path has no host identity. It is not mounted by the default preset.

`workspace-dependencies`, `worktree`, `cordis` and native Finder/open entries remain local-only by design or are outside the SSH file plane; they are not the same cwd-loss bug. ACP takes the client's `cwd` directly and is not a supported SSH-workspace entry point in this acceptance.

## Edge-case matrix

All rows below used the isolated DSH instance and the real `dshlab@127.0.0.1` workspace. "Remote" means the tool result or file existed only under `/home/dshlab`; the host user could not read it locally.

| Edge | Result |
| --- | --- |
| headless starts at anchor root | Pass: Session cwd anchor; grep/read/bash remote |
| headless starts at an existing anchor subdirectory | Pass: Session cwd `<anchor>/src`; pathless grep, relative read and bash all remote |
| subagent with no `cwd` | Pass: child inherits anchor; grep remote |
| subagent with relative `cwd: "src"` | Pass: child cwd `<anchor>/src`; `grep path "."` and relative `read` remote |
| subagent with absolute remote `cwd` | Pass: child cwd `<anchor>/src`; remote results |
| child relative `read ../remote-only.txt` | Pass: remote parent file |
| child relative `grep path ".."` / `glob path ".."` | Pass: remote parent tree, including spaces and Unicode names |
| child relative `write ../../outside/evil.txt` | Denied by workspace-write policy; no local fallback |
| absolute anchor path for read/write/grep | Pass: resolved to remote paths |
| absolute remote path for read/grep | Pass |
| spaces and Unicode in names | Pass: read, glob and grep under `space dir/中文 文件.txt` |
| leading-dash directory as grep root (`-dash`) | Pass: kept behind `--` and searched remotely |
| remote directory symlink (`link-src -> src`) | `read link-src/app.ts` is rejected by the helper's no-symlink policy; `grep path link-src` follows it. This is a known consistency boundary, not a routing fallback. |
| subagent `cwd: ".."` from the workspace root | Fails before the child starts: DSH pre-resolves it to the Host anchor-parent path, which is then interpreted as a remote path and rejected with `EACCES`. Needs a Host-vs-remote contract fix; not guessed in this branch. |
| bash command containing an absolute anchor path | The shell runs remotely, so the Host anchor path does not exist there; use relative or remote paths. Workdir routing itself is covered. |
| legacy Session header already stored as bare POSIX | Not repaired; recreate the Session from the SSH workspace. |

The symlink and subagent-`..` rows are documented boundaries, not regressions in the fixed path cases.

## Boundaries

- The acceptance prompt sent model requests only to verify the model-facing `grep`/`glob` tools in the isolated DSH profiles.
- Headless runs were bounded by an external timeout after the final JSON event; this record does not claim a new process-shutdown contract.
- Windows Desktop UI and a long-lived Web UI were not part of this acceptance. The affected code path is shared by Host filesystem routing and does not change the Client bundle.

# 0.13.9 acceptance — headless SSH search

Date: 2026-11-18. Plugin candidate: `0.13.9` built from the reviewed branch; helper `0.13.5` unchanged.

## Environment

- Independent DSH runtimes: `@deepseek-ai/dsh@0.2.1-rc.2` and `@deepseek-ai/dsh@0.2.2-rc.3`, installed under separate local prefixes. Neither used the globally installed DSH.
- Separate `DSH_HOME` and profiles for every runtime; the plugin was installed from the candidate `.tgz` into the `headless` profile.
- Real SSH: the host connected to `dshlab@127.0.0.1` through a temporary OpenSSH alias. The remote project lived at `/home/dshlab/project` with mode `0700`, so the host user could not read it locally. The alias and test user were removed after acceptance.
- No production profile, workspace mapping, SSH configuration or remote file was used.

## Before the fix

Started `dsh --profile headless` from the SSH workspace anchor:

```console
{"type":"session","sessionId":"session-212e…","cwd":"/home/dshlab/project"}
{"type":"status","phase":"turn_end","turn":1,"reason":{"kind":"error","error":{"message":"EACCES: permission denied, realpath '/home/dshlab/project/.git'","code":"UNKNOWN"}}}
```

The Session header was the bare remote POSIX path, so `grep` ran as the local user against an unreadable local path. On `ssh localhost` with the same path readable locally, the same bug can silently return local results.

## After the fix

Same runtime and anchor, with the candidate package:

```console
{"type":"session","sessionId":"session-f77c…","cwd":"<isolated DSH_HOME>/ssh-workspace-anchors/project · dshlab [e0d2659f]"}
...
"Found 2 files containing DSHLAB_MARKER…"
- /home/dshlab/project/remote-only.txt — line 1: DSHLAB_MARKER_UNIQUE
- /home/dshlab/project/src/app.ts — line 1: export const dshlab = "DSHLAB_MARKER_UNIQUE";
```

The SSH invocation log recorded the remote `rg` run for the workspace. A separate `glob` run on 0.2.2-rc.3 returned `./src/app.ts` with the same anchor cwd. The test `runtime-router.test.ts > keeps the headless Session cwd probe on the local SSH anchor` covers the router contract without a model request.

## Boundaries

- The acceptance prompt sent model requests only to verify the model-facing `grep`/`glob` tools in the isolated DSH profiles.
- Headless runs were bounded by an external timeout after the final JSON event; this record does not claim a new process-shutdown contract.
- Windows Desktop UI and a long-lived Web UI were not part of this acceptance. The affected code path is shared by Host filesystem routing and does not change the Client bundle.

# 0.13.9 — Headless/CLI Session cwd keeps SSH identity

## Changes / 更新

- Fix `dsh headless` and CLI Sessions started from an SSH workspace anchor. DSH seeds the Session header with `fs.processPath(await fs.resolve("."))`; the plugin used to resolve that probe through SSH and persist a bare remote POSIX path, so later `glob`/`grep` treated the Session as local.
- Keep the local anchor for that bare probe. The official working-directory service then restores the SSH host from the anchor, as it already does for Web Sessions, child Sessions and `cd`.
- Keep explicit relative `grep`/`glob` roots and relative `read`/`write`/`edit` paths relative to the remote Session cwd. The previous build could resolve them against the Host process cwd, so a child at `.../src` or a Session after `cd` searched the workspace root; `path: "."` was the visible case.
- Explicit remote targets, absolute anchor paths and display/file paths keep their existing routing. No host is guessed from a bare POSIX path.
- Add router regressions for the headless cwd probe, relative filesystem paths and relative ripgrep roots. Helper stays **0.13.5**, SHA-256 `95749359a6a0b6523fd34ac951eb78baf97757da4f5b8b0ab3aea7095ab14708`; no new Host RPC, runtime dependency, install step or permission change.
- 中文：修复从 SSH 工作区启动的 `dsh headless` / CLI 会话把远端 POSIX 路径写进 header、导致后续 glob/grep 在本机执行的问题；同时修正子代理或 `cd` 到子目录后相对搜索根和相对文件路径被按本机 cwd 解析的问题。保留本地 anchor，交给官方目录服务恢复主机；不按裸路径猜主机，helper、权限和接口不变。

## Install / 安装

Paste into the official Desktop/Web plugin page:

```text
https://github.com/CrazyShout/dsh-ssh-remote/releases/download/v0.13.9/dsh-ssh-remote-0.13.9.tgz
```

```sh
dsh plugin --profile web add 'https://github.com/CrazyShout/dsh-ssh-remote/releases/download/v0.13.9/dsh-ssh-remote-0.13.9.tgz'
```

For a headless/CLI profile, install into that profile and restart the one-shot process:

```sh
dsh plugin --profile headless add 'https://github.com/CrazyShout/dsh-ssh-remote/releases/download/v0.13.9/dsh-ssh-remote-0.13.9.tgz'
```

Save work before reloading. Runtime dependencies still download at installation; Desktop and Web profiles are separate.

## Verification / 验收

- Router regression: a bare `.` probe under an SSH anchor resolves to the local anchor; relative filesystem and search roots stay with the remote cwd; absolute anchors and explicit `ssh://` targets still map by host.
- Independent local DSH runtimes **0.2.1-rc.2** and **0.2.2-rc.3**, separate profiles and `DSH_HOME`, real `ssh localhost` to an isolated remote user whose project is unreadable to the host user.
- Before the fix: the headless Session header was `/home/dshlab/project`, and `grep` ran locally and failed with `EACCES`. After the fix: the header is the SSH anchor, and grep/glob return `/home/dshlab/project/...` through remote ripgrep.
- Subagents: a child with no `cwd` inherited the anchor and searched remotely; a child with `cwd: "/home/dshlab/project/src"` reported the anchor `/src` and searched remotely. Before the relative-root fix the same child's `grep path: "."` returned the parent `remote-only.txt`; afterwards it returned only `./app.ts`. Relative `read`/`write` in that child also stayed under the remote `src`.
- See [acceptance](0.13.9-acceptance.md) for the commands and evidence. Helper content and hash are unchanged.

## Compatibility and limits / 兼容与边界

- DSH targets remain 0.2.0-rc.2, 0.2.1-rc.2, 0.2.1-rc.3, 0.2.2-rc.1, 0.2.2-rc.2 and 0.2.2-rc.3. No DSH upgrade, new Host RPC or runtime dependency.
- The headless fix applies when the process starts inside a registered SSH workspace anchor or a descendant. A Session header already persisted by an older build as a bare remote POSIX path has no host identity; create a new Session from the same SSH workspace instead of guessing a host from that path.
- Relative search roots and relative file paths now follow the remote Session cwd. Absolute local anchors and explicit `ssh://` URIs still map by host; a bare absolute remote path without a cwd or owner anchor remains unresolvable by design.
- Headless is a one-shot model runner; the plugin still validates the Session directory through the SSH helper on first use. The acceptance runs serialize the final answer and were bounded by an external timeout; they do not claim a new shutdown contract.

## Rollback / 回退

Install the pinned [v0.13.8 archive](https://github.com/CrazyShout/dsh-ssh-remote/releases/tag/v0.13.8) through the official installer and reload after saving work. Existing workspace identities, Sessions and files are retained. v0.13.8 retains the headless cwd limitation described above.
